## 0. 使い方（Soumaへの運用指示）

資料作成の依頼を受けたら、次の順序でこのメモリを参照する。

1. **案件タイプを特定** → セクション1の「テンプレート全体マップ」から対応する完成テンプレを選ぶ
2. **スライド種別ごとのパーツを選ぶ** → セクション2〜7のパーツライブラリから該当スライドを引用
3. **共通デザイン規則を適用** → セクション8の「共通ブランド規則」に従う
4. **Google Slides でテンプレートを複製 → 中身を差し替える**形で出力する（ゼロから描画しない）

## 2. 案件タイプ別推奨構成

### A. 企画提案書（10スライド基本構成）
**ベース：完成テンプレ_企画提案書**

1. 表紙 — タイトル+サブタイトル+日付+会議名+作成者+LOGO+CONFIDENTIAL（01から）
2. 目次（CONTENTS 01-10形式、02から）
3. 提案サマリー / エグゼクティブサマリー（04から）
4. 現状分析（グラフ+メッセージ、05から）
5. 原因と課題（ロジックツリー型、05から）
6. 解決策・打ち手（Point 01/02/03カード、03から）
7. 企画詳細（比較データ、05から）
8. 目標設定・期待効果（Before→After、06から）
9. 必要費用（料金プラン型、05から）
10. 体制図（プロジェクト体制、05から）
11. スケジュール（ガント、05から）

### B. 会社紹介資料（7〜10スライド基本構成）
**ベース：完成テンプレ_会社紹介資料**

1. 表紙（COMPANY DECK / COMPANY PROFILE）
2. 目次（01 会社概要 / 02 MVV / 03 事業内容 / 04 メンバー / 05 採用）
3. Mission & Vision（左右2カラム or 3カラム）
4. 会社概要（key-value テーブル：会社名/所在地/事業内容/従業員数/資本金/設立年度）
5. 経営陣紹介（写真+役職+経歴カード×3〜4人）
6. 事業内容（Product 01/02/03）
7. 売上推移グラフ（吹き出しでマイルストーン）
8. 福利厚生・働き方（3x3グリッド）
9. 働く社員の声（Voices 引用カード）
10. グレード・給与レンジ（棒グラフ+グレード分布）
11. 全社組織図（ツリー型）
12. 選考フロー・募集職種
13. CEOメッセージ / We Are Hiring!（裏表紙）

### C. サービス紹介資料（10〜13スライド基本構成）
**ベース：完成テンプレ_サービス紹介資料**

1. 表紙（サービス名+Updated日付+LOGO+主要KPI 2つ）
2. INDEX（01 お悩み / 02 サービス概要 / 03 メリット / 04 事例 / 05 料金 / 06 導入の流れ・FAQ）
3. よくあるお悩み TOP3（3カラム課題カード）
4. サービスとは？（ビジネスモデル図：求職者⇔エージェント⇔企業 形式）
5. 数字で見るサービス（大きな数字＋補足）
6. 導入効果（Point 01 × Point 02 = Benefit の掛け算式）
7. 導入効果インパクト（Before→After対比）
8. 導入事例（課題/目的/成果＋お客様の声引用）
9. 料金プラン（初期費用+成功報酬形式 or 3プラン比較）
10. 他社との違い（競合比較表）
11. 導入までの流れ（STEP 01-04）
12. FAQ（Q&A形式）
13. お問い合わせ（メール+電話）

### D. 月次報告・レポート（10スライド基本構成）
**ベース：完成テンプレ_報告資料**

1. 表紙（○年○月 ○○月次報告）
2. INDEX（エグゼクティブサマリー / KPI / 施策別詳細 / 新規施策 / 競合 / 課題 / 来月方針 / 予算 / リスク / Q&A）

4. KPIダッシュボード（達成/未達バッジ＋数値）
5. 施策別詳細レポート（チャネル別グラフ）
6. 新規施策の進捗
7. 競合・市場動向 / ポジショニング分析
8. 課題抽出・優先度設定
9. 来月の方針・アクションプラン
10. 予算計画・期待ROI

## 3. パーツライブラリ①：表紙・章扉（01より）

### 表紙バリエーション（採用頻度順）
- **COMPANY DECK型**: 大文字欧文 "COMPANY DECK" + 和文「会社説明資料」+ 会社名 + Last Updated日付
- **COMPANY PROFILE型**: 縦並び "COMPANY / PROFILE" + 会社紹介資料 + 日付
- **提案会議型**: 「○○に関する提案」+ サブタイトル（〜）+ 会議名 + 作成日 + 部署/氏名 + CONFIDENTIAL + LOGO
- **サービス紹介型**: サービス名 + 「サービス紹介資料」+ Updated日付 + 主要KPI（5,000社 / 96.8%）
- **月次報告型**: 「2024年○月 マーケティング月次報告」+ 作成者 + CONFIDENTIAL
- **セミナー型**: タイトル + 日時 + 場所 + 主催会社 + 登壇者
- **イベント告知型**: 大見出し + 参加特典 + 先着N名 + 完全無料等の装飾バッジ

### 章扉（セクション区切り）
- 大きな番号 "01" + セクション名（COMANY / BUSINESS / MEMBERS / CULTURE 等の欧文+和文）
- ページ全体を使い、本文スライドと強いコントラストを作る
- Copyright fotoer: `© 2025 Company Name. All Right Reserved.` / `©ABC COMPANY Inc. All Rights Reserved.`

## 4. パーツライブラリ②：目次（02より）

### TOC バリエーション
- **番号＋項目型**: 01-05の円形番号＋和英併記タイトル
- **ページ番号付き型**: 項目 ・・・・・・ P05（点リーダー）
- **章タイトル型**: COMANY / SERVICES / MEMBERS / CULTURE の大文字欧文グループ
- **提案書10項目型**: 01-10 = 提案サマリー / 現状確認 / 原因と課題 / 解決策 / 企画概要 / 企画詳細 / 目標設定 / 費用 / 体制図 / スケジュール
- **会社紹介5項目型**: 会社概要・沿革 / ビジョン・ミッション / 事業内容・プロダクト / メンバー紹介 / 選考フロー・募集職種
- **報告資料10項目型**: エグゼクティブサマリー / KPI / 施策別詳細 / 新規施策 / 競合 / 課題 / 来月方針 / 予算 / リスク / Q&A

## 5. パーツライブラリ③：箇条書き・フロー・サイクル（03より）

### 箇条書き（5〜6項目）
- **縦積み型**: 01-05の番号+見出し+本文 の縦並び
- **2x3グリッド型**: 6項目を2列3段で配置、左に大きな番号
- **アイコン型**: 丸アイコン+見出し+本文

### フロー
- **横矢印型**: STEP 01 → 02 → 03 → 04 → 05（矢印接続）
- **縦タイムライン型**: 左に年（2010-2024）、右に出来事
- **2カラム対比型**: 左右に並列するプロセス

### サイクル
- **4フェーズ循環**: Latency / Transformation / Expansion / Integration
- **PDCAサイクル**: PLAN → DO → CHECK → ACTION の円環
- **5段階循環**: プランニング → デザイン → 開発 → テスト → レビュー

## 6. パーツライブラリ④：MVV・ステップ・サマリー（04より）

### ミッション・ビジョン・バリュー
- **左右2カラム**: Mission / Vision 並列
- **3カード型**: Mission / Vision / Value 大見出し+本文
- **アイコン吹き出し型**: 大きな引用符 "+Mission+引用風本文

### 成長ロードマップ
- **Phase 01-04型**: 2024-2026 / 2027-2029 / 2030-2033 の時系列フェーズ
- **階段型**: LEVEL 01〜05 段々上昇

### 沿革・History
- **年号グリッド**: 2015 / 2016 / 2018 / 2020 / 2024 + 各年のマイルストーン
- **タイムライン型**: 横軸年次、マーカーに吹き出し

### CEOメッセージ
- **右写真+左テキスト型**: 大見出し（主張1行）+ 本文（3段落）+ 代表取締役CEO 氏名
- **引用符強調型**: "" 大きな引用符で囲んだメッセージ

### エグゼクティブ・サマリー
- **KPIカード並列型**: 6つのKPI（売上/営業利益/契約社数/顧客単価/経常利益/EBITDA）
- **ハイライト+方針型**: 数値3つ + 次期事業方針4項目

## 7. パーツライブラリ⑤：図解・グラフ・表（05より）

### フレームワーク図
- **TAM-SAM-SOM**: 3重の同心円+市場規模数値
- **3C分析**: Customer / Competitor / Company 3つの円
- **SWOT**: 2x2マトリクス
- **ポジショニングマップ**: XY軸+ブランドロゴ配置
- **セグメント別マトリクス**: 2x2（大手/中小 × 既存/新規 等）

### 組織図
- **ピラミッド型**: 取締役会 → 部門 → チーム
- **二管掌並列型**: CEO管掌領域 / CCO管掌領域
- **体制図（プロジェクト用）**: リーダー+メンバー名、チーム別に4ボックス

### スケジュール / ガント
- **フェーズ別ガント**: 四半期を横軸に、部門別帯グラフ（研究開発部/製造部）
- **4カラム進行型**: 12月〜1月 / 2月〜3月 / 4月 + 現状フェーズ記号
- **CSチームフロー**: タスク別×タスク担当のマトリクス

### グラフ
- **売上推移（棒グラフ）**: 吹き出しでマイルストーン注記
- **前年比較折れ線**: 複数年を並列で比較
- **ドーナツ+KPI**: 中央に数字、周囲にラベル
- **円グラフ（構成比）**: 年代別、職種別
- **四半期棒グラフ+POINT枠**: 右側にトピックス箇条書き

### KPIダッシュボード（6マス）
- 売上高 / 有料会員数 / 営業利益 / 解約率 / アプリDL数 / 従業員数
- 各マス：大きな数字 + 昨対比％

### 表
- **比較表**: 行=機能、列=プラン/競合
- **会社概要表**: 左列=項目名、右列=値
- **Before/After比較**: 左右2列、行=指標

## 8. パーツライブラリ⑥：会社概要・FAQ・紹介（06より）

### 会社概要
- **key-value型**: 会社名/所在地/事業内容/従業員数/資本金/代表者/設立年度
- **Photo+key-value組合せ型**: 代表写真 + 会社名右寄せブロック

### Before/After
- **2列対比**: 左「導入前」右「導入後」 + 下部に数値改善率
- **3課題×3解決型**: 問題❶❷❸ / 解決策❶❷❸
- **Before→Arrow→After**: 矢印付き

### FAQ
- **Q&A縦並び**: Q: 質問 / A: 回答（3〜6セット）
- **2列FAQ**: 左右に3問ずつ
- **アイコンQ付き**: 丸ラベル Q + 質問

### 自己紹介カード
- **写真+肩書+経歴**: 左写真、右に氏名/ローマ字/役職/大学/前職履歴
- **経営メンバー3〜4人並列**: 各カードに写真+役職+氏名+経歴300字

### 社員の声 Voices
- **写真+引用符+見出し+本文+部署氏名**: "" 引用符で挟んだ吹き出し型
- **3人並列**: 3列でそれぞれのストーリー

### 裏表紙（Closing）
- **THANK YOU!**: ご清聴ありがとうございました
- **We Are Hiring!**: 採用サイトQR+エントリー案内
- **お問い合わせ**: メール + 電話 + 営業時間
- **ブランドロゴ+タグライン**: 単純な締め

## 9. 共通ブランド規則（厳守）

### カラー運用
- **メインアクセント**: テンプレートごとに1色を主役にする（Navy系/Deep Red系/Orange系/Green系）
- **ベース**: 白背景、ダーク文字（#222〜#333）
- **サブグレー**: #E8E8E8〜#F5F5F5（背景分離に使用）
- **注意**: テンプレート指定時はそのテンプレートのカラーから1mmも動かない

### タイポグラフィ
- **見出し（日本語）**: 太字明朝 or 太字ゴシック、32-44pt
- **サブタイトル（欧文）**: 細字欧文・Sans-Serif、14-18pt（見出しの上/下に配置）
- **本文**: ゴシック体、11-14pt
- **重要数値**: 60-120ptの特大サイズ、色アクセントで強調

### レイアウト
- **ヘッダー余白**: セクション番号（01〜10）を右上 or 左下に小さく配置
- **フッター**: 著作権表記 + 会社名 + ページ番号
- **スライドメッセージ**: 本文上部に1-2行（50〜60文字以内）で主張を明示
- **余白**: 上下40〜60px、左右50〜80px

### 必須要素
- **表紙**: タイトル + サブタイトル + 日付 + 作成者/会社名 + LOGO + （必要なら）CONFIDENTIAL
- **章扉**: 大きな番号 + 欧文 + 和文 の3要素セット
- **本文スライド**: 右上または左下に「セクション番号+タイトル」+ 上部にメッセージ1行 + 本文エリア + 著作権フッター
- **裏表紙**: THANK YOU / We Are Hiring / お問い合わせ いずれか

### 頻出文字列（そのまま流用可）
- `Last Updated YYYY.MM.DD`
- `Updated YYYY.MM.DD`
- `© 2025 Company Name. All Right Reserved.`
- `©ABC COMPANY Inc. All Rights Reserved.`
- `CONFIDENTIAL`（左下小さく）
- `LOGO`（ロゴ配置placeholder）
- `Photo`（写真配置placeholder）
- `ここにはスライドメッセージが入ります。本スライドで伝えたいことを端的に1,2行でまとめるようにしましょう。`（本文誘導文）

### 禁止事項
- テンプレート指定時のカラー・フォント独自変更
- 同一スライドに3色以上のアクセントカラーを使う
- 数値以外で 60pt 超の大文字を使う（視線が散らばる）
- 1スライドに情報を詰め込みすぎる（5〜7要素まで）
- 写真placeholderをそのまま出力する（差し替えるか、抽象背景に切替）

## 🚀 2026年7月 スキル強化アップグレード（オーバースペック化）

日本国内の資料デザイン記憶エージェントとして「唯一無二」の到達点を目指すため、Souma のデザインメモリ機能を体系的に拡張する。ここから下は、既存のテンプレート/パーツライブラリ管理に加えて、Design DNA・Design Token・Component Library の3層構造で扱う「デザインシステム記憶エージェント」としての追加装備である。既存セクション（0〜12）を上書きせず、必ずこの補強レイヤーを最後に参照して意思決定に反映すること。

### 追加専門知識

**1. Design DNA（ブランドの遺伝子コード化）**
Design DNA とは、ブランドが「なぜその形・色・言葉を選ぶのか」の意思決定基準を、再現可能なコードとして残す考え方である。Souma は案件ごとに次の6軸で Design DNA を抽出・保存する：(1) Purpose（存在意義）、(2) Personality（人格：Serious/Playful/Trustworthy/Innovative の4象限）、(3) Tone of Voice（敬体/常体/専門/やさしさ）、(4) Visual Principles（余白比・グリッド比・角丸半径）、(5) Symbolic Motif（幾何形/有機形/文字図形）、(6) Emotional Target（読後に読者に残したい感情1語）。これを YAML/JSON 化してテンプレート URL とセットで保持し、次回同一クライアント案件が来た際に即座にリロードできる形にする。

**2. Design Token 体系（W3C Design Tokens Community Group 準拠）**
2026年時点で W3C の Design Tokens Format Module がドラフトから安定版に移行し、Figma・Style Dictionary・Tokens Studio 間で JSON 相互互換が確立した。Souma は次の3層でトークンを管理する：(a) Global Tokens（原子的値：#0A2540, 8px, 1.5 line-height など）、(b) Alias Tokens（意味付き：color-brand-primary, spacing-md）、(c) Component Tokens（用途固有：button-primary-bg, card-padding）。トークン変更履歴は SemVer（1.2.0 のような形式）で管理し、`design-tokens.json` を Google Drive フォルダ直下に配置する。

**3. Component Library（原子→分子→有機体→テンプレート）**
Atomic Design 準拠で、既存11ファイルのパーツを Atoms/Molecules/Organisms/Templates/Pages に再分類する。例：Atoms=数字ラベル・アイコンチップ・引用符、Molecules=KPIカード・自己紹介カード、Organisms=KPIダッシュボード6マス・TAM-SAM-SOM同心円、Templates=完成テンプレ5種、Pages=納品済み最終スライド。これによりパーツ検索粒度が細かくなり、「KPIカードだけ差し替えたい」という要望に3秒で応えられる。

**4. Style Guide 2026年最新動向**
(1) Bento Grid（不均等な矩形分割で情報密度を上げる、Apple/Vercel 発）、(2) Neubrutalism 系の高コントラスト再来（B2B資料でも採用増）、(3) Kinetic Typography（Google Slidesでも段階アニメで実装可能）、(4) Data Humanization（数値の隣に「≒東京ドーム3個分」のような比喩を添える）、(5) Accessibility First（WCAG 2.2 AA準拠：コントラスト比4.5:1以上、フォント最小12pt）。これらは既存の日本語B2B資料に「オーバースペックな一手」として組み込める。

**5. Notion/Miro/Figma 横断ナレッジ**
Google Slides 中心のワークフローでも、Notion のブロックエディタ的発想（トグル・カラム・データベース）、Miro のインフィニットキャンバス発想（並列比較）、Figma の Auto Layout 発想（余白の自動計算）を Slides のオブジェクト配置に応用することで、修正コストを半減できる。

### AI活用スキル拡張

**1. Figma AI（First Draft / Make Designs）連携**
Figma AI の First Draft 機能で叩き台を生成 → エクスポート → Google Slides に画像貼り付け → 再構成、というワークフローを既定にする。Souma はプロンプト設計担当として、以下のプロンプトパターンを保持：「B2B 建設業界向け、Deep Navy #0A2540 基調、Bento Grid 3x3、KPIカード6枚、日本語見出しゴシック、Slide 16:9」。プロンプトはクライアント別に `prompts/{client}.md` として保存する。

**2. Design System AI（Zeroheight / Supernova）**
海外の主要デザインシステム（Material 3, Fluent 2, Carbon, Polaris, Atlassian）を Zeroheight で横断検索し、日本語 B2B 資料に応用できるパターンを日次で採取する。特に Data Visualization ガイドライン（Carbon Charts, Atlassian Chart Library）は月次報告資料に直接転用可能。

**3. AI Guideline 検索エンジン（自前構築）**
Souma のメモリを RAG（Retrieval Augmented Generation）化する。手順：(a) 本ファイル + パーツライブラリ URL 内テキスト + 過去納品スライドを Embedding 化（text-embedding-3-large 想定）、(b) ベクトル DB（Vercel Postgres pgvector 想定）に保存、(c) 案件依頼時に「導入事例スライド、建設業、成功報酬」等のクエリで類似ケース TOP3 を返す。これで「過去に似た資料あった気がする」の勘に頼らない検索基盤が完成する。

**4. AI駆動レビュー（Claude + Vision）**
生成された Google Slides の PNG エクスポートを Claude Vision に投げ、以下を自動チェック：(1) セクション9の共通ブランド規則違反、(2) コントラスト比 4.5:1 未満、(3) 1スライド8要素超過、(4) フォントサイズ11pt未満の混入、(5) placeholder テキスト残り。Mana の QA 前に自動フィルタとして機能させる。

**5. 実践的ワークフロー（オーバースペック標準）**
案件受領 → RAG 検索で類似案件抽出 → Design DNA 更新 → Figma AI で叩き台 → Google Slides 実装 → Vision AI レビュー → Mana QA → Sora QA → 納品。全工程で60分以内を目標とする（従来は240分想定）。

### 危機管理・デザインナレッジ喪失対策

**1. 属人化リスクの排除**
Souma 個人の暗黙知が失われる最大要因は「頭の中だけにある判断基準」である。対策：(a) 全ての意思決定を本ファイルに文章化、(b) 「なぜこのパーツを選んだか」の理由を案件ごとに `decisions/{date}-{client}.md` に残す、(c) Rin/Aoi/Mana に月1回「Souma 判断基準勉強会」を開催し、代替可能性を担保する。

**2. ドキュメント欠落対策**
Google Drive のオリジナルテンプレが削除/移動されると、本ファイルの URL がすべて 404 になる致命的リスクを持つ。対策：(a) 全11ファイルを月次で `backup/{YYYY-MM}/` にコピー、(b) スクリーンショット PDF を Notion DB に添付、(c) SHA-256 ハッシュを記録して改ざん検知、(d) オーナー（eiyoshi99@gmail.com）とは別に自社アカウントで閲覧権限を確保。

**3. Version Drift（バージョン乖離）対策**
Design Token・パーツ・完成テンプレのバージョン不整合が最大の品質リスク。対策：(a) SemVer 準拠でバージョン管理、(b) 破壊的変更（Major）は必ずセクション12の差分学習履歴に理由を明記、(c) 過去バージョンのスナップショットを最低3世代保持、(d) 案件受領時に「使用バージョン」をヘッダに明記する運用を徹底。

**4. ブランド乖離（Brand Drift）検知**
案件を重ねるうちに徐々にブランド規則から逸脱する現象。対策：四半期ごとに直近納品30本を Vision AI で走査し、セクション9違反率が3%を超えたら赤信号として Yuto と Sora にアラート。

**5. AI 依存の逆リスク**
AI 生成の叩き台に依存しすぎると、Souma 自身の判断力が退化する。対策：月1回「AI 使用禁止デー」を設け、素の実力で1案件を仕上げる訓練を義務化。

**6. データ主権・機密漏洩**
クライアント情報を含むスライドを外部 AI に投げるリスク。対策：(a) クライアント名・数値・固有名詞はマスキング後に AI 投入、(b) 商用利用可のオンプレ LLM（Claude API 経由）以外は禁止、(c) 案件終了後30日で AI ログを完全削除。

**7. 障害時のフォールバック**
Figma AI / Google Slides 障害時は、Miro + PowerPoint での代替ワークフローを事前定義。SLA目標：主要ツール障害時も4時間以内に代替経路で納品開始。
