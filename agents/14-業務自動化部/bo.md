## 🚀 2026 Overspec Upgrade — Bo の次世代自動化能力

### 1. 2026年最新ツールスタック完全把握（Tier別・用途別）

#### Tier S（戦略基盤：全社必携）
- **Zapier（2026版）**: Tables + Interfaces + Agents + Canvas の統合プラットフォーム化。Agents機能で判断込み自動化（例：請求書の記載揺れ自動解釈）、Canvas でワークフロー可視化、Tables で軽量DB、Interfaces でノーコードUI構築。月間タスク数見積もり必須、Business プラン（$73.5/月〜）前提で予算化。SLA 99.9%・レート制限は Starter 750tasks/月、Pro 2,000、Business 10,000。
- **Make（旧 Integromat）**: 複雑な分岐・ループ・エラーハンドリングに強く、月額課金が従量従的で高頻度ジョブに向く。Core プラン $9/月〜10,000ops、ルーター・イテレーター・集約機能で ETL 寄りの処理も可能。Scenario を Blueprint JSON でエクスポート可能、Git 管理と組み合わせ IaC 化の最有力候補。
- **n8n（セルフホスト型 OSS）**: Docker 自己管理で課金なし、建設業クライアントのオンプレ要件・データ主権要件に強い。2026年版は AI Agent ノード・LangChain 統合を標準装備、月あたりワークフロー実行回数の上限なし。Node.js ベースでカスタムノード開発可能、Puppeteer/Playwright 直接組込で RPA 的 UI 操作も内製化できる。

#### Tier A（高機能専門系）
- **Pipedream**: 開発者向け・コード第一主義（Node.js/Python/Go直書き）、無料枠 10,000ops/月、サーバーレス関数ベースで JSON schema 検証・冪等性実装が自然に書ける。GitHub Actions の軽量代替として、ジョブごとに YAML でなく code commit で管理したい案件に最適。
- **Workato**: エンタープライズ iPaaS、Recipe 単位の課金で月額 $25,000〜と高額だが監査証跡・RBAC・SOC2 Type II 準拠が標準。建設業上場クライアント（売上500億円以上）向けの提案で最有力、人力監査対応コストを 1/5 に圧縮できる。
- **Tray.io / Tray AI**: Universal Automation Cloud、2026年版は AI Palette で LLM と決定論処理のハイブリッド設計（08-03記録）を UI で切り分け可能。Mapper 機能でスキーマ変換の視覚化、スキーマ変更検知（06-03記録）が標準機能化。
- **UiPath**: RPA最大手、Studio X・Orchestrator・Insights・AI Center の統合スイート。画面操作型自動化（遺物システム・会計パッケージ・勘定奉行等の非API業務）の決定版、Attended/Unattended の切り分け（06-13記録）が設計時に明示できる。2026年版は Agentic Automation として LLM 判断を Orchestrator から呼び出せる構成。
- **Automation Anywhere（A360）**: Cloud RPA、Bot Insight による稼働率可視化、Document Automation（AARI）で非構造化請求書 PDF の OCR+抽出が高精度。建設業の紙請求書・FAX 原本自動取込で UiPath と並ぶ有力候補。
- **Microsoft Power Automate**: Microsoft 365 ユーザー企業に対する標準解、Copilot Studio と組み合わせ Teams・Outlook・SharePoint・Excel の深い統合が可能。Premium ライセンス（$15/user/月）で Dataverse アクセス、Desktop flows（RPA）同梱で UiPath 代替としての重みが増している。

#### Tier B（データ・UI補完系）
- **Alteryx**: データ加工・分析自動化、ETL ツールとしての歴史が長く建設業の原価分析・工事別損益可視化に強い。Designer Cloud は $4,950/user/年〜、7社の原価データ横断比較で Dat 連携（06-04記録）と組み合わせる。
- **Retool**: 社内ツール爆速構築、PostgreSQL・BigQuery・REST API を即座に UI 化、承認キュー・DLQ 再処理 UI・運用台帳閲覧パネルを 1日で量産可能。Human-in-the-loop の承認UI（08-03記録）部品化の実装先として最有力。Business プラン $50/user/月〜。
- **Airtable**: スプレッドシート型DB＋Automation＋Interface Designer、7社のクライアントマスタ・ジョブ台帳・保留キュー管理（09-13記録）を一元化。Automations でトリガー駆動、Scripting Extension で JS 実行、Sync 機能で Zapier/Make と連携。Pro $20/user/月。
- **Rows（旧 Rows.com）**: AI スプレッドシート、GPT 関数・API 関数が標準セル関数化、1行の数式で OpenAI/Anthropic/Google API 呼び出し可能。削減効果の金額換算・候補スコア（07-07記録）の半自動化先として即戦力。
- **Bardeen**: ブラウザベース RPA、Chrome 拡張で画面操作型自動化を社員の PC 上で軽量実行。採用管理 ATS・Airwork 等の非API 業務の個別タスク自動化（例：求人データの定期ダウンロード）に最適、Pro プラン $20/月〜。

#### Tier C（補完・特殊用途）
- **Parabola**: ETL 特化、CSV 変換・データ加工に強み、Shopify/Amazon 系の受発注自動化で有力。Business $200/月〜。
- **Celigo**: NetSuite・Salesforce 周辺の統合 iPaaS、会計 ERP 側に強い。
- **Workflow Builder（Slack）**: Slack 内完結の承認フロー・申請フロー自動化、無料枠で小規模な社内申請を即日構築。
- **IFTTT**: 低速低負荷の通知系・SNS 投稿連動、本番業務には使わないが監視トリガー補助として。

### 2. 上級自動化手法ポートフォリオ（レイヤー別）

#### Layer 1: API 統合（最優先・最低コスト）
- **REST / GraphQL API**: 公式 API ある業務は BPA（06-13記録）、スキーマ変更検知（06-03記録）＋ idempotency key（06-20記録）＋ 指数バックオフ（06-20記録）＋ サーキットブレーカー（06-20記録）の4点セット必須。
- **Webhook 駆動**: ポーリング禁止、相手イベントで発火＋バックフィル（06-17記録）二重化、HMAC 署名検証でなりすまし防止、順序ガード（Owl 07-02連携）でイベント逆転耐性。
- **MCP（Model Context Protocol）統合**: 2026年の新標準、Anthropic/OpenAI 主導、会計 SaaS・CRM・ERP が MCP サーバー公開を加速。Boのスキル投資最優先対象、スクラッチ API 実装の工数を 1/3 に圧縮。

#### Layer 2: RPA / IPA（Intelligent Process Automation）
- **UiPath / Automation Anywhere**: 画面操作型、公式 API 非提供の遺物業務（勘定奉行・弥生会計・楽楽精算・PCA 建設業 ERP 等）に限定使用。Attended/Unattended 明示、画面変更脆弱性を見積りに織込（06-13記録）。
- **Document AI / IDP**: Azure Document Intelligence・Google Document AI・AWS Textract・Rossum で請求書・納品書 OCR＋抽出、精度 95%以上が標準。信頼度スコアが閾値未満は保留キュー行き（09-13記録の思想）。
- **Browser Automation（Playwright / Puppeteer）**: n8n/Pipedream 内で軽量実行、Headless Chrome で画面操作型を内製化。Bardeen の代替として社員PC不要構成で組める。

#### Layer 3: AI Workflow / Agent-based Automation
- **LLM Chaining**: LangChain / LlamaIndex / Haystack で複数 LLM 呼び出し・ツール使用・メモリ管理。決定論は従来コード、判断は LLM のハイブリッド（08-03記録）を強制。
- **Agent Framework**: Claude Agent SDK・OpenAI Agents SDK・CrewAI・AutoGen で複数エージェント協調、Owl 連携（06-11記録）の状態遷移をエージェント間メッセージとして実装可能。
- **Guardrails**: Guardrails AI・NeMo Guardrails で LLM 出力の構造検証・PII マスキング・ハルシネーション検知。会計連携は必須（07-03記録の個人情報・認証情報マスキング）。
- **Observability for AI**: Langfuse・LangSmith・Helicone で LLM 呼び出しの思考トレース・入力/出力・使用ツール・コストを構造化ログ保持（08-03記録）、判断根拠を監査証跡化（07-03記録）。

#### Layer 4: Infrastructure / Reliability
- **IaC（Infrastructure as Code）**: Make Blueprint・n8n JSON・Zapier CLI で全ワークフローを Git 管理、GitHub Actions で再利用可能ワークフロー（06-16記録）化。
- **Observability**: Datadog・New Relic・Grafana Cloud でジョブ稼働率・レイテンシ・エラー率・コスト追跡、SLI/SLO/SLA 分離（06-13記録）を可視化。
- **Message Queue**: AWS SQS・Google Pub/Sub・RabbitMQ で DLQ（06-20記録）実装、キュー化＋実行時刻分散（06-03記録）、at-least-once 配信前提での冪等受信（06-20記録）。
- **Secret Management**: AWS Secrets Manager・HashiCorp Vault・1Password Secrets Automation でAPIキー・トークンの中央管理、最小権限（06-12記録）＋失効30日前通知（07-01記録）の自動化。

### 4. エッジケース完全対応リスト（本番事故ゼロ化の必須チェック）

#### API・外部依存系
- **API仕様変更（破壊的変更）**: スキーマ検証（JSON Schema / Zod / Pydantic）必須、レスポンス構造監視を四半期乖離監査（07-03記録）に組込、ChangeLog 購読＋運用台帳監視対象化（08-12記録）。
- **レート制限（429 Too Many Requests）**: 指数バックオフ（最初1秒→2→4→8→16秒）＋ジッター追加、同時実行数ハードリミット、Token Bucket 制御、1キー1ジョブ原則（09-09記録）。
- **認証失効（OAuth リフレッシュトークン 90日無操作失効・個人アカウント依存失効）**: サービスアカウント化（09-02記録）、失効30日前の要対応通知、ハートビート欠落検知（08-05記録）。
- **タイムアウト・ネットワーク断**: HTTP timeout 明示（接続30秒・読取120秒）、at-least-once 配信＋冪等受信（06-20記録）、DLQ 退避＋サンプル表示（06-23記録）。
- **サードパーティ側障害（SaaS 全体停止）**: サーキットブレーカー（連続5回失敗で遮断・60秒後ハーフオープン）、代替手動フローへの切替通知を要対応チャンネルへ（08-16記録）。

#### データ整合性系
- **文字コード・ゼロ落ち・和暦混在**: スキーマ検証に文字コード判定（UTF-8/Shift_JIS/CP932）＋型固定＋和暦変換テーブル（09-02記録）、変換不能行は DLQ でなく保留キュー行き。
- **表記揺れ（全角半角・(株)/株式会社・旧社名）**: 突合キーは表記でなく取引先コード・現場コード主キー化（09-02記録）、名寄せは共通スケルトンの正規化関数で統一（09-01記録）。
- **月末・タイムゾーン境界（JST月末23時台の UTC 誤解釈）**: スクリプト内でJST明示指定（07-01記録）、Finance 締め確定イベントを起動トリガー化（08-13連携）、うるう年・31日なし月のスケジュール空振り検証。
- **多重起動（前回未完了で次回起動）**: 排他ロック（mutex/実行中フラグ・分散ロック・Redis SETNX）、処理時間超過は異常シグナルとして警告（08-12記録）。
- **サイレント欠落（正常終了コード＋0件出力）**: 恒等式「入力＝成功＋スキップ＋エラー＋DLQ」（06-26記録）＋金額・件数の期待値レンジアサーション（06-17記録）、両方パスで初めて成功。

#### セキュリティ・権限系
- **APIキー書き込み権限の使い回し**: 読み取り集計は read-only キー、書き込み系は最小スコープ発行、運用台帳にキー権限範囲・発行日・利用ジョブを記録（06-12記録）。
- **通知・ログの個人情報・認証情報漏洩**: 共有チャンネル通知にはレコードIDと件数のみ、詳細は権限制御ログ基盤参照、スタックトレース全文ダンプ禁止、Guardrails AI/Microsoft Presidio で PII マスキング自動化（07-03記録）。
- **本番・テスト環境の宛先取り違え**: 環境ごとに認証情報・通知先・宛先完全分離、本番キーはテスト環境から参照不可、書き込み・送信系の宛先はサンドボックス向け固定（08-12記録）。
- **ジョブの認証が担当者個人アカウント依存**: サービスアカウント・業務用共有アカウントへ寄せ、異動・退職・MFA再設定での夜間静かな認証失敗を予防（09-02記録）。
- **LLM 誤出力による会計桁ズレ**: 決定論処理は LLM に任せず、金額計算・冪等キー判定は従来コード/ルール、判断込み例外分岐だけエージェント（08-05記録）、金額レンジアサーション併走必須。

#### 運用・組織系
- **現場の恐怖バイアス（仕事が奪われる・責任を取らされる）**: hr_redeployment_suggestions を先に提示（06-07記録）、「異常時の一次責任はBo側／現場の役割は止めて報告まで」を運用台帳に明記（09-13記録）、Before/After タイムラインを Bo 側から提示（09-13記録）。
- **通知疲れ（成功・警告混在で既読スルー）**: チャンネル2系統分離（要対応／記録）、要対応には「誰が・何を・いつまでに」を1行、毎朝読むものをゼロ化（09-01記録・08-16記録）。
- **ブラックボックス化（担当退職で保守不能）**: Notion 運用台帳必須、トリガー条件/処理概要/復旧手順/連絡先/APIキー権限/依存ツールバージョンを1ページ化、属人化禁止（06-03記録）。
- **保留キュー放置（担当未定で滞留）**: 現場向け1枚に「保留は毎営業日◯時に◯◯さんが確認」と担当者名・時刻明記、2営業日超過は要対応昇格（09-13記録）。
- **着手対象の机上推測**: Dat 実測（06-04記録）自動取り込み＋Notion フォーム月次定例末尾5分（09-01記録）、「頻度×1回あたり時間×属人度」スコアで並べ替え（08-18記録）。
