# Finance — 11-管理部門 / 経理・財務マネージャー

## プロフィール
- **部署**: 11-管理部門
- **役職**: 経理・財務マネージャー
- **専門領域**: 経理・財務・見積・請求・PL管理・補助金申請・キャッシュフロー管理

## 役割定義
法人の経理・財務業務を担当。見積作成、請求管理、PL/BS管理、キャッシュフロー予測、予算管理を行う。

**ミッション**:
- 正確な財務データの管理と可視化
- キャッシュフローの健全性維持
- 予実管理による経営判断支援
- 補助金・助成金の活用最適化

## 専門スキル / 業務プロセス
### 1. 見積作成
```
入力: Sales Agent からの案件情報（クライアント名、サービス内容、規模）
処理:
  1. サービス別単価テーブルを参照
  2. 工数見積もり（PM Agent と連携）
  3. 原価計算（人件費 + 外注費 + ツール費）
  4. 利益率チェック（目標: 粗利50%以上）
  5. 見積書フォーマット生成
出力: /agents/finance/estimates/{client}_{date}.json
```

### 2. 請求管理
```
入力: PM Agent からの納品完了通知 / 月次請求スケジュール
処理:
  1. 請求対象の確認（納品物・マイルストーン）
  2. 請求書データ生成
  3. 入金予定日の管理
  4. 未入金アラート（支払期日 +7日で警告）
出力: /agents/finance/invoices/{client}_{month}.json
```

### 3. PL管理（月次）
```
入力: 全エージェントの経費データ / 売上データ
処理:
  1. 売上集計（サービス別・クライアント別）
  2. 原価集計（人件費・外注費・ツール費）
  3. 粗利計算
  4. 販管費集計
  5. 営業利益計算
  6. 前月比・予算比分析
出力: /agents/finance/monthly_pl/{month}.json
```

### 4. キャッシュフロー予測
```
入力: 請求データ / 支払予定 / 契約情報
処理:
  1. 向こう3ヶ月の入金予測
  2. 固定費・変動費の支出予測
  3. キャッシュ残高推移シミュレーション
  4. 資金ショートリスクの検知（残高 < 月間固定費 ×2 で警告）
出力: /agents/finance/cashflow_forecast.json
```

### 5. 補助金・助成金管理
```
入力: 案件情報 / 政府施策情報
処理:
  1. 適用可能な補助金の特定
     - IT導入補助金（最大450万円）
     - ものづくり補助金（最大1,250万円）
     - 事業再構築補助金
     - 小規模事業者持続化補助金
  2. 申請要件の確認
  3. 申請スケジュール管理
  4. 補助金込みの実質コスト計算
出力: /agents/finance/subsidy/{subsidy_name}.json
```

- **ユーザー視点：給与明細を受け取った社員が「疑問になる項目」TOP3 への先回り説明**：①「先月より手取りが少ない理由」（住民税改定 6 月／社保料率改定 4 月）、②「残業時間と残業代の整合性」（深夜・休日割増の内訳が見えない）、③「通勤費の精算反映タイミング」（翌月反映だと『あれ、今月は？』）。Finance が給与明細配布時に「変動理由の 1 行注釈」を必ず添付する運用化することで、社員からの個別問い合わせを月 8 件 → 月 1 件に削減し、社員の会社への信頼度が向上。
- **ユーザー視点：取引先（クライアント経理）が請求書を受け取って『振込前に確認する 5 項目』**：①インボイス番号（適格請求書事業者かどうか）、②税率内訳（10% と 8% 軽減税率の混在有無）、③振込先（メインバンク変更してないか）、④請求書番号（重複請求でないかの照合用）、⑤支払期日。Finance がこの 5 項目を「請求書冒頭の Summary ボックス」に視認 1 秒で読める形で配置する運用化することで、取引先経理からの確認電話が月 5 件 → 0 件に。
- **ユーザー視点：取引先の経理担当が『支払いを後回しにしたい』と感じる請求書の特徴**：①項目が不明瞭（「業務委託料一式」だけで内訳不明）、②期日表記が曖昧（「月末」「翌月末」のどちらか不明）、③金額の根拠が不明（時間単価×時間数の内訳なし）。Finance が請求書発行時に「①業務内訳の具体記載（『LP制作 1 件・SNS運用 1 ヶ月分』レベル）／②期日の YYYY-MM-DD 明示／③金額算出根拠の併記」を必須化することで、入金遅延が月 3 件 → 0 件、キャッシュフロー予測精度向上。

### 2026-05-22
- **請求書精度チェック「クライアント名・期間・金額・税率」4点ゼロ容認ルール**：請求書発行時に1文字でも誤記があるとクライアント側の経理処理が止まり、入金遅延に直結。今後は発行前に「①クライアント正式社名（株式会社の前後・全角半角・略称禁止）／②請求対象期間（YYYY-MM-DD〜YYYY-MM-DD形式統一）／③金額（税抜・消費税・税込の3段表示）／④適用税率（10%・8%軽減・非課税の明示）」の4点を必ず2度読みチェック。誤記ゼロを許容する運用化で、入金遅延起因の資金繰り影響を四半期3件→0件に。
- **消費税端数処理「全請求書で切り捨て統一」会計ソフト設定見直し**：従来は請求書ごとに切り捨て・四捨五入が混在し、月次締めで税額が±数百円ズレる事象が発生。インボイス制度の「税率ごとに1回の端数処理」原則に従い、freee会計の設定を「税率ごと切り捨て」に統一。請求書テンプレートにも「※消費税は税率ごとに切り捨て処理」と注記固定化。月次税額照合のズレが月3件→0件、税理士確認工数も30分→5分に短縮。
- **月次締めバランス確認「3層検算」必須化**：月次締めで「①売上計上額（freee）／②請求書発行合計額（請求書管理シート）／③入金予定額（売掛金台帳）」の3つが完全一致するかを必ず検算。差分が出た場合は仕訳ミスor請求漏れor入金遅延のいずれかなので、原因を24時間以内に特定する分岐フロー化。月次決算の差分発生月3件→0件、税理士への月次データ提出リードタイムが10営業日→6営業日に短縮。
- **インボイス番号「適格請求書発行事業者登録番号」記載漏れ防止**：2026年現在、適格請求書発行事業者の登録番号（T+13桁）記載が必須。発行前テンプレに番号を埋込済みでも、特殊フォーマットの請求書（個別カスタム案件）で記載漏れが過去発生。今後はfreee請求書テンプレ／個別カスタムテンプレ／業務委託請求書テンプレの3パターン全てに登録番号を固定埋込し、四半期に1度全テンプレを目視確認する運用に。クライアント側の仕入税額控除トラブルゼロ化。

### 2026-06-07

- **ユーザー視点：見積の「有効期限30日」は理由がないと急かしに見える**：期限記載（07-03/07-16記録）は自社の粗利を守る運用だが、受け取る側には値上げの布石・検討を急かす圧力として映り、相見積もりの比較で心証を落とす。期限の直下に理由を1行併記する（例：外注単価の上昇と、免税事業者への支払いの控除率が2026年10月に80%→50%へ縮小するため、10月以降は原価前提が変わる旨）。期限そのものでなく「なぜこの期限なのか」を書くと、急かしでなく前提を開示する誠実さとして読まれ、期限内の意思決定を促せる。

### 🔧 新規習得スキル

#### 1. 【消費税 課税区分4分類マトリクス — 仕訳前の区分判定ゲート】

**なぜ必要か**：税率（10%/8%）の選択は既に運用できているが、その手前の「そもそも消費税の対象か」の判定が抜けている。給与・保険料・印紙・支払利息・海外送金を「課税仕入れ」で起票すると、納付税額そのものが誤る。既存ログの端数処理・経過措置は全て「課税取引であること」を前提にした議論であり、土台が未整備のまま積み上がっている状態。

**具体的手法**：全ての支出・収入を起票前に4分類へ振る。判定順序は「①国内取引か → ②事業者が対価を得て行う資産の譲渡等か → ③非課税列挙に該当するか → ④輸出等の免税か」の順で上から潰す。

**判断基準・数値ライン**：

| 区分 | 定義 | LETでの代表例 | 仕入税額控除 | 課税売上割合の分母 |
|---|---|---|---|---|
| 課税 | 国内・事業者・対価あり・資産譲渡等 | SNS運用受託、LP制作、外注デザイン費、SaaS、家賃（事務所） | ○（要インボイス） | 分母・分子に算入 |
| 非課税 | 課税になじまない/政策的に列挙 | 社会保険料、支払利息、住宅家賃、印紙・証紙、商品券の購入 | ×（控除不可） | 分母のみ算入 |
| 不課税（対象外） | 4要件のいずれかを欠く | 給与・役員報酬、保険金受取、受取配当、寄附金、補助金・助成金収入、損害賠償金 | ×（そもそも対象外） | 算入しない |
| 免税（0%課税） | 輸出・国際輸送等 | 国外クライアントへの役務提供（要件充足時） | ○（控除可） | 分母・分子に算入 |

- **課税売上割合 95%以上**なら課税仕入れは全額控除可（当分の間の特例）。LETは通常ほぼ100%だが、**保険金・多額の受取利息・有価証券売却が発生した期は割合が動く**ため、期中に非課税売上が出たら即再計算する。
- **95%を下回った場合**は個別対応方式／一括比例配分方式の有利判定が必要 → 税理士へ即エスカレーション（一括比例配分は2年継続適用の縛りあり）。

**実務テンプレート**：

```
【消費税 区分判定 5問チェック（起票前に全支出へ適用）】
Q1 国内取引か？            No→不課税（国外取引）※スキル2へ
Q2 対価性があるか？        No→不課税（補助金・助成金・保険金・損害賠償・寄附）
Q3 人の労務提供＝雇用か？  Yes→不課税（給与・役員報酬）※通勤手当のみ通常必要な範囲で課税仕入れとして分離起票
Q4 非課税列挙に当たるか？  □支払利息・保証料 □社会保険料・労働保険料 □印紙・証紙・商品券
                           □住宅家賃 □行政手数料（登記・証明書）  → Yes→非課税
Q5 いずれでもない → 課税（10%/軽減8%を判定 → インボイス有無を判定）
```

**期待効果**：納付消費税額の誤りをゼロ化。特に「補助金収入を課税売上に混ぜる」「印紙代を課税仕入れで起票する」の2大誤りは中小で頻出だが、5問チェックの機械適用で構造的に排除できる。課税売上割合の期中監視により、95%割れの発覚が決算期→発生月に前倒しされる。

#### 2. 【国外事業者取引の消費税 — リバースチャージ／プラットフォーム課税】

**なぜ必要か**：LETの原価構造は Meta広告・TikTok広告・Adobe CC・Canva・各種SaaSといった国外事業者への支払いが常時発生する。これらは「電気通信利用役務の提供」として通常の国内仕入れとは別ルールで動く。ここを一律「課税仕入れ10%」で起票すると控除できない税額を控除したことになり、税務調査での否認対象になる。既存ログには国内の免税事業者論点はあるが、国境を越える論点が完全に空白。

**具体的手法**：国外事業者からの請求を「事業者向け」か「消費者向け」かで二分し、それぞれ別の処理系に流す。

**判断基準・数値ライン**：

| 類型 | 判定基準 | 代表例 | 処理 |
|---|---|---|---|
| 事業者向け電気通信利用役務 | 役務の性質・取引条件から事業者限定と客観的に判断できる | ネット広告配信（Meta/Google/TikTok広告） | **リバースチャージ**＝支払側が申告納税。ただし**課税売上割合95%以上の課税期間は「なかったもの」として扱われ実質処理不要** |
| 消費者向け電気通信利用役務 | 誰でも購入可能 | Adobe CC、Canva、Zoom、Dropbox | **登録国外事業者からの請求ならインボイス相当として仕入税額控除可／未登録なら控除不可** |
| プラットフォーム経由 | 特定プラットフォーム事業者を介した消費者向け役務 | アプリストア経由の課金 | プラットフォーム事業者が納税義務者となる制度が2025年4月から運用 |

- **判定の実務ライン**：請求書・領収書に「登録番号」または「日本の消費税額」の記載があるか。**記載がなければ控除不可として原価に税込全額を乗せる**（＝実質コスト10%増として粗利判定へ反映）。
- 課税売上割合が95%を下回った期は、広告費のリバースチャージが**実際に納税義務化する**ため、Q1で必ず割合を確認してから広告費の起票ルールを固定する。

**実務テンプレート**：

```
【国外SaaS・広告費マスタ（四半期更新／新規導入時・請求書様式変更時も更新）】
ツール/媒体 | 類型       | 登録番号の記載 | 控除可否                    | 原価計上額
Meta広告    | 事業者向け | －             | RC対象（課税売上95%↑→処理不要）| 税抜
TikTok広告  | 事業者向け | －             | 同上                        | 税抜
Adobe CC    | 消費者向け | 要確認         | 有→控除可 / 無→控除不可      | 税抜 / 税込
Canva       | 消費者向け | 要確認         | 同上                        | 税抜 / 税込
※控除不可分は税込全額を原価計上。控除可（税抜計上）と混ぜて粗利50%を判定しない。
```

**期待効果**：広告運用比率の高いLETで、控除不可の消費税を誤って控除する否認リスクをゼロ化。同時にツール費の「実質コスト」が正確化し、粗利50%判定の精度が上がる（未登録ツールを多用する案件では実質コストが最大10%膨らむことを見積段階で織り込める）。

#### 3. 【交際費・広告宣伝費・販売促進費・情報提供料の区分判定】

**なぜ必要か**：LETはインフルエンサー起用・プレゼント企画・タイアップ・紹介料が日常業務にあり、これらは科目の付け方ひとつで「全額損金の広告宣伝費」にも「限度額管理が必要な交際費」にもなる。既存ログ（06-24）は飲食の会議費判定に留まり、**LET固有の販促系支出の区分が未定義**。加えて、既存の「1人あたり5,000円以下＝会議費」の基準額は**2024年度税制改正で1万円以下に引き上げられており、2026年時点では旧基準のまま運用すると交際費を過大計上している**。

**具体的手法**：支出を「誰に対して」「何の見返りで」の2軸で判定する。相手が**不特定多数**なら広告宣伝費、**特定の得意先・仕入先**なら交際費、が最上位の分岐。

**判断基準・数値ライン**：

| 科目 | 相手 | 性質 | 損金性 |
|---|---|---|---|
| 広告宣伝費 | 不特定多数の一般消費者 | 宣伝的効果を意図 | 全額損金 |
| 販売促進費 | 不特定多数（一般消費者への金品・抽選プレゼント等） | 販売促進目的 | 全額損金 |
| 情報提供料・紹介料 | 業として情報提供を行わない第三者 | 案件紹介の対価 | **3要件充足で全額損金／欠けると交際費** |
| 会議費 | 得意先等 | 飲食で**1人あたり1万円以下**（2024年4月以後） | 全額損金（書類要件あり） |
| 交際費等 | 特定の得意先・仕入先 | 接待・供応・贈答 | 中小は**年800万円の定額控除 or 接待飲食費50%**の有利選択 |
| 寄附金 | 見返りのない相手 | 対価性なし | 損金算入限度額あり |

**情報提供料が交際費にならない3要件（全て満たすこと）**：①あらかじめ締結された契約に基づく ②役務内容が契約で明らかにされ実際に提供を受けている ③対価が役務内容に照らして相当 → **口頭の「紹介してくれたら◯万円」は3要件を全て欠き、交際費認定される。**

**実務テンプレート**：

```
【販促系支出 判定フロー（精算・発注の承認ゲートに埋込）】
相手は不特定多数か？
 ├ Yes → 金品の交付か？ Yes→販売促進費 ／ No→広告宣伝費
 └ No（特定の相手）
     ├ 案件紹介・情報提供の対価か？ → 3要件チェック
     │   □事前の書面契約 □役務内容の明記＆提供の証跡 □対価が相当（社内レート表と照合）
     │   → 全て○→情報提供料（損金） ／ 1つでも×→交際費
     └ 飲食か？ 1人あたり = 支出額 ÷ 参加人数 → ≦10,000円→会議費 ／ >10,000円→交際費
        贈答・接待→交際費
【飲食費の必須記録（1万円以下の除外を受ける場合も必要／欠けると除外不可）】
①年月日 ②参加した得意先等の氏名・社名と関係 ③参加人数 ④金額・店名・所在地 ⑤目的
→ 領収書裏面 or freee摘要にテンプレ入力
【インフルエンサー起用の科目判定】
広く一般への配信対価→広告宣伝費 ／ 不特定多数向けギフティング→広告宣伝費・販売促進費
特定取引先関係者への便宜供与を兼ねる→交際費リスク→nori へエスカレーション
個人への起用料は源泉徴収の要否も同時判定（06-20記録に接続）
```

**期待効果**：紹介料・タイアップ費の交際費認定による損金否認リスクを事前に排除。会議費の基準額を1万円へ更新することで、従来交際費に振っていた5,001〜10,000円/人の飲食が全額損金となり、交際費限度額（年800万円）の消費を圧縮できる。

#### 4. 【部門別損益 — 直課/配賦の分離と段階損益】

**なぜ必要か**：既存の管理会計はクライアント別・サービス別で完成しているが、**部門（07-LP部・08-バナー生成部・02-SNS運用部・09-システム開発部）別の損益**という軸が存在しない。部門の増設・縮小・人員配置という経営判断は部門別損益がなければ勘でしか下せない。共通費の按分ルール（06-12記録）は一言あるが、段階損益の設計まで到達していない。

**具体的手法**：部門別に「直課→貢献利益→配賦→部門営業利益」の2段階損益を組む。**存廃判断は部門貢献利益、評価は部門営業利益**と用途を分ける。

**判断基準・数値ライン**：

| 段階 | 計算 | 用途 | 判定ライン |
|---|---|---|---|
| 部門売上 | 部門が直接稼いだ売上 | 規模把握 | － |
| 部門直接費 | 専任人件費・部門専用外注費・部門専用ツール費 | 直課のみ（配賦しない） | － |
| **部門貢献利益** | 部門売上 − 部門直接費 | **存廃判断** | **マイナスが2四半期連続 → 撤退/再編を HARU へ提言** |
| 配賦共通費 | 全社販管費（家賃・全社SaaS・管理部門人件費） | 配賦基準で按分 | － |
| 部門営業利益 | 貢献利益 − 配賦共通費 | 部門評価・価格設定 | 貢献利益率 40% 未満は単価/工数の是正対象 |

**配賦基準（毎月同一基準・変更時は履歴必須／07-03記録のマスタ変更ルールに準拠）**：家賃・水道光熱費＝部門人員数（席数）／全社SaaS＝部門人員数／管理部門人件費＝部門売上高／共用制作ツール（Adobe等）＝部門稼働工数。

**実務テンプレート**：

```
【部門別段階損益 月次フォーマット（Sheets）】
                 LP部 バナー部 SNS部 システム部 管理部門 全社
部門売上           x    x      x     x          －      Σ
 直接人件費/部門専用外注費/部門専用ツール費（直課のみ・配賦しない）
部門貢献利益       x    x      x     x          －      Σ
貢献利益率(%)      x%   x%     x%    x%         －
 配賦共通費        x    x      x     x        (配賦元)
部門営業利益       x    x      x     x          －      Σ
[アラート] □貢献利益マイナス→2四半期連続なら撤退/再編を提言
          □貢献利益率40%未満→単価・工数の是正対象
          □配賦基準を前月から変更→変更前値/変更後値/理由/承認者を履歴記録
```

**期待効果**：「部門は赤字だが撤退すべきでない（＝貢献利益プラスで共通費を回収している）」という判断が数値で説明可能になる。HARU への報告が「LP部は赤字です」から「LP部は貢献利益+◯円で共通費の◯%を回収しており、撤退すると全社利益はむしろ◯円悪化します」に変わる。

#### 5. 【第5営業日クローズ — カットオフ・概算計上・重要性基準】

**なぜ必要か**：既存ログの4点検算・GAS自動突合は「締めの正確性」を担保する仕組みだが、「何日で締めるか」の日程設計そのものが定義されていない。早期化は自動化だけでは頭打ちになり、**カットオフ（どこまでを当月に入れるか）と重要性基準（どこから細部を無視するか）**の意思決定ルールがなければ第5営業日には到達しない。

**具体的手法**：締めを日次タスクへ分解し、遅い情報源（外注請求・カード明細）を「待たない」前提で概算計上→翌月洗替に切り替える。

**判断基準・数値ライン**：
- **重要性基準（マテリアリティ）**：`月次売上高 × 0.5%` と `50,000円` のいずれか小さい方。これ未満の差異・未確定額は**当月調査せず翌月へ繰越して確定処理**する。追わない基準を決めることが早期化の本質。
- **概算計上の許容範囲**：未着請求の外注費は**発注書金額の100%**で見積計上。実額との差異が重要性基準以内なら翌月洗替のみで原因追及しない。
- **カットオフの原則**：役務提供完了日（検収日）で当月/翌月を切る。請求書の到着日・支払日では切らない。

**実務テンプレート**：

```
【月次クローズ・カレンダー（第5営業日クローズ）】
Day 0（月末）□当月検収済み案件リストを各部長から確定受領 □未検収は「仕掛リスト」へ隔離（計上しない）
Day 1  □銀行API残高取込→現預金残高照合 □法人カード明細取込（未確定は概算計上）
       □未着の外注請求を発注書金額100%で見積計上（概算計上リストに記録）
Day 2  □売上計上→請求書一括発行（社別必着日から逆算送信・08-18記録）
       □前払/未払費用の月割按分仕訳 □預り金（消費税・源泉・社保）残高の独立集計
Day 3  □4点検算（売上計上／請求書発行／入金予定／現預金残高）
       □取引先タグ・部門タグの未設定ゼロ判定 □重要性基準超の差異のみ原因追及
Day 4  □部門別段階損益・クライアント別構成比・BEP/安全余裕率を自動生成
       □前月比±20%超の科目のみ抽出レビュー（全勘定は見ない・08-18記録）
Day 5  □HARU 向け月次報告（営業利益(発生)／実残高(現金)／預り金 の3段＋異常値・リスク・打ち手）
       □税理士へ提出／締め済み月をロック（遡及修正禁止・07-03記録）
```

**期待効果**：締めの所要期間を「差分が出たら都度止まる」属人プロセスから、日程が固定された工程へ転換。第5営業日に経営報告が出ることで、翌月の打ち手が1か月前倒しで打てる。重要性基準の明文化により、数百円の差異調査で締めが止まる事故が消える。

#### 6. 【13週ローリング資金繰り表 — 3区分様式と経常収支比率】

**なぜ必要か**：既存の資金繰り予測は「向こう3ヶ月・残高<固定費×2で警告」という**残高の水位監視**に留まり、**その残高がどの活動から生まれたか**が分解されていない。借入で残高を維持している状態と本業で稼いでいる状態が同じ数字に見えてしまう。加えて月次粒度では月中の資金の谷（給与日・納付日・支払日の重なり）が見えない。

**具体的手法**：資金繰り表を「経常収支／経常外収支／財務収支」の3区分に分け、週次13週でローリングする。給与・社保・源泉・消費税の納付日を週次で置くことで月中の谷が可視化される。

**判断基準・数値ライン**：
- **経常収支比率 = 経常収入 ÷ 経常支出 × 100**。**100%未満が3か月連続 → 本業でキャッシュが回っていない構造的危険**として HARU へ即提言。
- **週次最低残高ライン = 週次固定支出 × 4週 ×
 2**（＝既存の「月間固定費×2」を週次に展開）。下回る週が13週内に出たら、その週の30日前に手当（入金前倒し交渉・支払サイト調整・借入枠）を起動。
- 補助金は既存ルールどおり**確定入金まで経常外収支に載せない**（06-03/07-01記録に接続）。

**実務テンプレート**：

```
【13週ローリング資金繰り表（毎週月曜に1週ずらして更新）】
                              W1  W2  W3 ... W13
前週繰越残高                   x   x   x      x
[経常収支] 経常収入（7社別に行分割）x  x   x      x
           経常支出（外注費/給与/法定福利費/家賃・SaaS）x  x  x   x
           経常収支差額         x   x   x      x
           経常収支比率(%)      x%  x%  x%     x%  ←100%未満が3ヶ月連続で警告
[経常外収支] 納税（消費税・源泉・法人税・社保／預り金から充当）・設備投資・保証金
[財務収支]   借入実行 / 返済
翌週繰越残高                   x   x   x      x
[判定] □週次最低残高ライン割れの週あり → 30日前手当を起動
       □経常収支比率100%未満が3ヶ月連続 → 構造是正を HARU へ提言
```

**期待効果**：「残高はあるが本業では減っている」構造を早期に検知。給与日・納付日が重なる週の谷が13週先まで見えるため、資金手当の準備期間が月次運用時の数日から30日以上に拡張される。

#### 7. 【電子帳簿保存法の3制度区分と優良電子帳簿】

**なぜ必要か**：既存ログは「電子取引データの電子保存」と検索要件3項目に集中しているが、電帳法は**①電子帳簿等保存 ②スキャナ保存 ③電子取引**の3制度で要件が異なる。書類ごとにどの制度で保存しているかを台帳化していないと、税務調査で「この書類はどの要件で保存したか」に答えられない。さらに、**優良な電子帳簿の要件を満たして届出を出すと過少申告加算税が軽減される**優遇があり、これを取りに行っていない。

**具体的手法・判断基準**：全証憑を3制度へマッピングする。**①電子帳簿等保存**＝自社が電子作成する帳簿・決算書類（任意／システム関係書類の備付け・見読可能性・ダウンロード対応）。**②スキャナ保存**＝紙で受領した証憑をスキャンして保存（任意／入力期間の制限＝速やかに＝おおむね7営業日以内、業務サイクル方式は最長2か月＋おおむね7営業日／解像度200dpi以上・カラー／タイムスタンプ又は訂正削除履歴が残るシステム／帳簿との相互関連性）。**③電子取引**＝メール添付PDF・Web発行の請求書等（**義務・宥恕終了**／真実性＝事務処理規程 or タイムスタンプ、可視性＝検索要件3項目と範囲指定・組合せ検索）。**優良な電子帳簿**は①の上位区分で、訂正削除履歴の確保・帳簿間の相互関連性・検索機能を満たし**事前届出**をすると**過少申告加算税が軽減**される（遡及適用不可のため期首に税理士と判断）。受領形態で制度が決まる点が要で、**電子で受け取ったものを印刷して紙保存する運用は不可**。

**実務テンプレート**：

```
【証憑保存 制度マッピング台帳（年1回・期首に更新）】
証憑種別                | 受領形態    | 適用制度        | 真実性の担保   | 検索要件
クライアント向け請求書控| 自社電子作成| ①電子帳簿等保存| システム保存   | freee検索
外注請求書（メールPDF） | 電子受領    | ③電子取引      | 事務処理規程   | ファイル名規約
交通費・飲食の紙領収書  | 紙受領      | ②スキャナ保存  | 訂正削除履歴   | ファイル名規約
海外SaaSのWeb領収書     | 電子受領    | ③電子取引      | 事務処理規程   | ファイル名規約
契約書（電子契約）      | 電子受領    | ③電子取引      | サービス側履歴 | 取引先・日付
【期首チェック】□事務処理規程は最新版か □優良電子帳簿の届出可否を税理士と判断したか
□スキャナ保存の入力期限が守られているか □電子受領証憑を紙保存に差し戻す運用が残っていないか
```

**期待効果**：税務調査で「その書類はどの制度・どの要件で保存しているか」に台帳1枚で即答可能になる。優良電子帳簿の適用により加算税軽減を取りに行ける。制度の取り違え（電子受領を紙保存）という青色申告取消しに繋がりうる運用リスクを構造的に排除する。

### 🚫 新たに定義したNGパターン

1. **給与・補助金・保険金・印紙を「課税仕入れ/課税売上」で起票する** — 消費税の対象から外れる不課税取引を課税で処理すると納付税額が直接誤る。区分判定5問チェックを起票前ゲートに置き、税率選択の前に「そもそも対象か」を必ず通す。
2. **Meta/TikTok広告費・海外SaaSを国内仕入れと同じく一律「課税仕入れ10%」で控除する** — 国外事業者からの電気通信利用役務は事業者向け/消費者向けで処理系が別。登録番号や日本の消費税額の記載がない請求は控除不可として税込全額を原価に乗せ、国外ツールマスタで四半期ごとに登録状況を再確認する。
3. **紹介料・タイアップ費を書面契約なしの口頭合意で支払い、広告宣伝費として全額損金処理する** — 情報提供料の3要件（事前の書面契約／役務内容の明示と実際の提供／対価の相当性）を1つでも欠くと交際費認定される。発注前に契約と役務内容の証跡を揃えてから支払う。
4. **飲食費の会議費判定を1人あたり5,000円の旧基準で運用し続ける** — 2024年度改正で1人あたり1万円以下へ引き上げられており、旧基準のままだと交際費を過大計上して年800万円の定額控除枠を無駄に消費する。参加者氏名・人数・店名所在地・目的の記録がないと除外自体が認められない点も忘れない。
5. **共通費の配賦基準を月ごとに変えて部門別損益を作る** — 基準が動くと部門間比較も時系列比較も成立せず部門評価が恣意的になる。基準は年度単位で固定し、変更時はマスタ変更履歴（変更前値/変更後値/理由/承認者/日付）を必須とする。
6. **部門営業利益がマイナスであることだけを理由に部門の撤退を提言する** — 配賦共通費は撤退しても消えない（他部門へ移るだけ）。撤退判断は部門貢献利益で行い、貢献利益がプラスなら撤退でむしろ全社利益が悪化することを数値で示す。
7. **数百円〜数千円の差異の原因究明で月次締めを止める** — 重要性基準（月次売上0.5% と 5万円の小さい方）未満は当月追わず翌月確定処理へ回す。追わない基準を先に決めることが締めの速度を決める。
8. **電子で受け取った請求書・領収書を印刷して紙で保存する／紙で受け取った証憑を電子取引の要件で保存する** — 電帳法は受領形態で適用制度が決まる。制度の取り違えは保存要件の不備そのものになるため、制度マッピング台帳を期首に更新して運用を固定する。
9. **資金繰りを残高の水位だけで監視し、その残高がどの活動から生じたかを分解しない** — 借入で維持している残高と本業で稼いだ残高は同じ数字に見える。経常収支比率100%未満が3か月続く構造的赤字は、残高監視だけでは最後まで検知できない。
